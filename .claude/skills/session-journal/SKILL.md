# Session journal

Schema: `pipeline/schema/journal.schema.json`. Design rationale: ADR-0008 and
`docs/research/02-campaign-tools.md` §4–6.

## Entities

`session{number, date, inWorldDate?, title?}` → `entry{at, kind, personId?, placeId?,
questId?, lootId?, text ≤ 120}`; rosters `person`, `place`, `quest{status}`, `loot{status}`.
Backlinks ("every entry mentioning X") are queries over `entries` — never stored.

## Entry kinds and glyphs (monochrome)

| kind | glyph | opens roster | default text |
|---|---|---|---|
| met | `@` | People (+ "at …" Place chip) | person's one-line detail |
| went | `→` | Places | — |
| quest | `?` | Quests (new quest = title) | objective line |
| got | `◆` | Loot (+ holder chip) | value |
| learned | `!` | — (free line) | — |
| rumor | `~` | — (free line) | — |
| note | `·` | — (free line) | — |

## Capture flow (≤ 10 s, wheel-first)

1. `+` on the session → 7-row kind list (wheel to move, tap or press to choose).
2. Roster for that kind, most-recently-mentioned first, "+ new" pinned at top. Choosing
   "+ new" is the only keyboard trip and asks for a **name only** (`singleLine`, `initialCaps`).
3. Optional link chips ("at …", "re …") open the Place/Quest rosters; skipping is one tap.
4. Optional one-line text (editor, single line). Save stamps `at = now`.

Renaming, merging ("Merik" → "Merrick"), and prose belong to the laptop after export.

## Bounds

One campaign per character (v1); rosters ≤ 200 each; entries per session ≤ 200; quests
show `open` by default with done/failed/dropped struck through at the bottom. Sessions are
numbered by the player; `number` may repeat (a "session 0" for downtime is fine).

## Export

- JSON: the schema document, pretty-printed, shown as text pages (v1) / QR pages (later).
- Markdown, Obsidian-shaped: one file per Person/Place/Quest with YAML `type`, `aliases`,
  `status`, `first_seen: Session N` **as properties**; one `Session NN.md` per session with a
  bullet per entry using the glyph and `[[wikilinks]]` for every linked name; an optional
  `fc-date` property when `inWorldDate` is set. Generated by `journal/MarkdownExport.kt`
  (pure, fixture-tested with a sample journal in `fixtures/journal/`).

## Never

No calendar model, no maps, no images, no relations-with-roles, no permissions/DM
visibility, no free-form Markdown editing on device, no unbounded search.
